# M3.1 Simulator and Ground-Truth Sidecar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, in-session; the owner has not asked for subagents). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the deterministic v2 telemetry simulator and its separate ground-truth sidecar, validate it against AC-01…AC-18 and AC-27…AC-32, and generate the frozen dataset.

**Architecture:** One new package `backend/simulator_v2/` (v1 `backend/simulator/` stays untouched). Per run, a pure pipeline: profile → workload/baseline → planned faults (simulated against the baseline) → latent signals on the 30 s grid → ticks/gaps/envelopes → Parquet rows + sidecar records. One run's data is held per worker; a coordinator only collects small summaries and writes the manifest. Telemetry rows contain no truth columns; truth lives only in sidecar JSONL.

**Tech Stack:** Python 3.12, numpy 1.26 (already installed), pyarrow 21 (Parquet), jsonschema (already a dependency), multiprocessing, psutil (peak memory). New optional extra `ml = ["numpy", "pyarrow", "psutil"]` in `backend/pyproject.toml`; no other dependency.

**Spec:** the accepted M3.0 specification v4.5.1, kept outside the repository (published artifact https://claude.ai/artifact/PWPcp56zxP4Py7sE6Xfwue; Markdown source in the session scratchpad). Section numbers below refer to it. It is deliberately not duplicated in the repo. Existing contract: `contracts/telemetry/v1/envelope.schema.json`.

## Global Constraints

- Every number, distribution, clip and class comes from the spec (§2–§4); no value is retyped from memory. `constants.py` holds them once, and tests assert them against spec text (§2 table).
- `protocol_version = "4.5"`; `protocol_hash` = SHA-256 of canonical JSON of `protocol.json`; `sampling_origin = "run_start"`; `buffered_membership = "true_sample_time"` (§1, §9).
- Event times on the 30 s latent grid; nominal ticks `n_k = run_start + k·cadence_s`; `u_k = max(n_0 + j_0, run_start)` for k = 0, else `n_k + j_k` (§8.2).
- Quotas (§10), 180 runs / 2,520 host-days, 1,300 merged incidents, 129 relapses, caps 1,000 outcome attempts and 100 run re-plans; failure aborts, never relaxes (§4.1, §5).
- Output under `artifacts/datasets/<dataset_id>/` (§9), git-ignored. No Supabase, no API replay, no ingestion changes, no `backend/.env` reads.
- Truth never appears in observation columns (§9, §7.4). Labels, features, models and dashboards are out of scope.
- Determinism: `numpy.random.SeedSequence.spawn` streams per run and per component (§17).

## Review Focus

- Planner infeasibility: runs where long lead-in faults (disk_fill up to 600 min, pool up to 480 min) leave no room; expect re-plan exhaustion to be reported as a blocker, never relaxed. Test: synthetic run with 15 long primaries aborts after exactly 100 re-plans.
- Float-time boundaries: gap/partition membership at `u_k == a` and `u_k == b`; mask end at `oracle_mask_end`; dedup-free exposure at 900 s equality. Tests use integer microsecond arithmetic.
- Rejection sampling bias: outcome checks must redraw whole parameter sets, not clip. Test: attempt counts recorded and ≤ 1,000, fault with forced mismatch aborts.
- Counter reset right-continuity and `floor(C(u_k))` precision near 2⁵³; test with C0 = 5e12 over 14 days at the maximum rate.
- Worker memory and determinism under multiprocessing: result bytes identical for 1 vs 8 workers.

## File Structure

- `backend/simulator_v2/constants.py` — all spec constants and distribution parameters.
- `backend/simulator_v2/rng.py` — `RunStreams(master_seed, run_index)` giving named `Generator`s.
- `backend/simulator_v2/protocol.py` — builds `protocol.json`, canonical JSON, hash.
- `backend/simulator_v2/footprints.py` — footprint table, classes F1–F10, matrix, `compatible()`.
- `backend/simulator_v2/profile.py`, `workload.py`, `baseline.py` — §3.1–§3.3, benign processes (§3.5).
- `backend/simulator_v2/faults/` — one module per family (`mem_leak.py`, `disk_fill.py`, `cpu_runaway.py`, `net_flood.py`, `pool_exhaustion.py`, `silent_crash.py`) plus `common.py` (impact effects §4.3, recovery §4.4, T_ret).
- `backend/simulator_v2/precursor.py` — §7 precursor_start, group, silent_reason.
- `backend/simulator_v2/planner.py` — §5; `merge.py` — §6 incidents and `oracle_mask_end`.
- `backend/simulator_v2/signals.py` — latent grid, noise, counters and resets (§3.4, §8.1).
- `backend/simulator_v2/ticks.py` — ticks, jitter, skew, gaps, omissions, envelopes, replay, accounting (§8.2–§8.5, §10.1).
- `backend/simulator_v2/writer.py` — Parquet, JSONL sidecars, manifest, view.json; `backend/ml/schema/*.json` — gt-1.0 schemas.
- `backend/simulator_v2/validate.py` — contract + semantic validation, independent audit entry point.
- `backend/simulator_v2/generate.py`, `__main__.py` — CLI (`python -m simulator_v2 generate|dev-fixture|audit`), worker pool, resource report.
- `backend/tests/m31/` — acceptance tests, one file per area.
